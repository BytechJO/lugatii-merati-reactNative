# تطبيق مرآتي لغتي — React Native

تطبيق موبايل مستقل عن `frontend`، مبني باستخدام Expo SDK 58 وReact Native وTypeScript. يستخدم نفس الباك إند وأرقام الدروس الحالية. لم يتم تعديل قاعدة البيانات أو تنفيذ طلبات كتابة على السيرفر أثناء التحويل.

## التشغيل بدون Android Studio

من مجلد المشروع الرئيسي افتح PowerShell:

```powershell
npm.cmd install
npm.cmd start
```

نزّل Expo Go على هاتف Android، واجعل الهاتف والكمبيوتر على نفس شبكة Wi-Fi، ثم امسح رمز QR. أمر `start` يستخدم `--go` صراحةً؛ لا يحتاج محاكي أو بناء APK. استخدم Expo Go الداعم لـSDK 58. على الآيفون، سجّل بنفس حساب Expo على الهاتف والتيرمنال باستخدام `npx expo login --browser`.

إذا لم يتصل الهاتف بالكمبيوتر، اسمح لـNode.js على الشبكة الخاصة في جدار الحماية. يمكن تجربة `npm.cmd start -- --tunnel`؛ يستخدم SDK 58 النفق المدمج الجديد دون الحاجة إلى ngrok.

## تشغيل محاكي Android مع DNS صريح

إذا كان المحاكي يصل إلى عناوين IP لكن تظهر `unknown host` لأسماء المواقع، أغلق المحاكي ثم شغّل من `mobile`:

```powershell
npm.cmd run emulator
```

يشغّل هذا الأمر `Medium_Phone_API_37.0` مع DNS ‏`8.8.8.8,8.8.4.4` ودون تحميل لقطة إقلاع قديمة. يحافظ على بيانات التطبيق وإعداد الرسوميات المحفوظ في AVD. يجب استخدام هذا الأمر في مرات التشغيل القادمة للحفاظ على DNS الصريح؛ تشغيل المحاكي من Device Manager لا يرث خيارات هذا الأمر.

بعد اكتمال إقلاع المحاكي، شغّل `npm.cmd start` واضغط `a` لفتح Expo Go. إذا كان Metro يعمل بالفعل، اضغط `a` في نافذته.

## الاتصال بالباك إند

العنوان الافتراضي هو نفس عنوان الويب المرفوع:

```text
https://arabic-learning-web-app.onrender.com
```

يمكن إنشاء ملف `.env.local` من `.env.example` وتغيير `EXPO_PUBLIC_API_URL`. هذا عنوان علني، ولا توضع فيه أسرار أو بيانات اتصال Neon. بعد تغيير العنوان أعد تشغيل Expo. عند استخدام باك إند محلي من الهاتف، استخدم عنوان الكمبيوتر على الشبكة؛ `localhost` على الهاتف يشير إلى الهاتف نفسه.

التوكن وبيانات الجلسة محفوظان داخل Expo SecureStore على الجهاز. كلمة المرور لا تُحفظ. شاشة اختيار نوع الحساب تمنع الدخول بدور مختلف عن الدور الذي يعيده الباك إند.

للمعاينة بالمتصفح شغّل `npm.cmd run web`. نسخة الويب تستخدم `sessionStorage` الخاصة بتبويب المتصفح؛ SecureStore يبقى مخصصاً للموبايل. إغلاق التبويب ينهي الجلسة المخزنة فيه.

## المسارات المنقولة في هذه النسخة

- اختيار الحساب وتسجيل الدخول والخروج واستعادة الجلسة.
- الرئيسية للطالب والمعلم.
- الانضمام إلى الصف وعرض الصف الحالي.
- قائمة الحروف مع حالة القفل والإنجاز للطالب ومعاينة المعلم.
- قائمة الأنشطة الستة لكل حرف.
- صفحات الحروف تستخدم شبكة المرجع، وخط Amiri Quran لأسماء الحروف، وبطاقات الأنشطة الست الأصلية، والهيدر الشفاف داخل الحرف والأنشطة. النمر والزخارف يظهرون على التابلت مع مساحة خاصة أسفل المحتوى، ويختفون على الهاتف.
- التعلّم والتلوين يبدآن بفيديو الشرح للدرسين 1 و2، ثم المحتوى التفاعلي. إن لم يوجد فيديو يمكن عرض المحتوى دون تسجيل مشاهدة وهمية. مكتبة الفيديوهات تعرض بطاقات المرجع وتفتح مشغلاً واحداً يمكن إغلاقه.
- تعلم الحرف، مع إعادة استخدام صور وأصوات الحروف الأصلية المتوفرة والنطق الآلي كبديل لبقية الحروف.
- أسئلة مكان الحرف والتشكيل، وحفظ الإجابات وتقدم الحرف.
- تشغيل الفيديو باستخدام مشغل Native، وحفظ نشاط الفيديو بعد انتهاء فيديو.
- تلوين الحروف باللمس، داخل قناع الحرف، وحفظ التقدم عند تغطية 98٪ من نقاط قياس الحرف.
- الألعاب الأربع: الذاكرة، التصنيف بالسحب أو اللمس، اصطياد الكلمات، والبالونات، مع حفظ النتائج وفحص إكمال درس الألعاب.
- لعبة «اصطد الكلمات» للطالب لها شاشة كاملة بخلفية التحميل واللعب الأصليتين، وشريط التعليمات والنقاط، ودوائر متساقطة بإطارات متقطعة. تستخدم دفعات وسرعة المرجع، وتتوقف في خلفية التطبيق أو عند مغادرة الشاشة. النتيجة تظهر في نافذة مع حفظها قبل إعادة اللعب؛ المعلم يستمر في المعاينة فقط.
- لعبة «صنّف الكلمات» تستخدم خلفية التحميل وبطاقات الكلمات الأصلية، وصندوقي التصنيف الأصفر والبنفسجي، وشريط النقاط وعدّاد الحركات. السحب يبدأ بعد تحريك الإصبع 8 نقاط، مع بطاقة عائمة فوق المحتوى وقياس الصناديق بإحداثيات النافذة. يمكن أيضاً اختيار كلمة ثم لمس الصندوق. إسقاط الكلمة خارج الصناديق لا يحسب حركة، والكلمة الموضوعة لا تحسب مرتين. يبقى حفظ اكتمال اللوحة كما كان؛ المحاولة المنتهية بحد الأخطاء تتيح إعادة اللعب دون اعتبار النشاط مكتملاً.
- لعبة «ذاكرة الحروف» تستخدم خلفية التحميل وظهر البطاقة من المرجع، وشبكة من أربع بطاقات في الصف تتكيف مع المساحة المتاحة دون تمرير أفقي. التقليب بحركة ثلاثية الأبعاد، والمطابقة تبقى ظاهرة بإطار ذهبي. فحص البطاقتين بعد ثانية، مع منع تقليب بطاقة ثالثة أثناء المقارنة، ومطابقة الحرف مع بداية الكلمة كما في الويب. حد الحركات 10، وتحسم مطابقة الحركة الأخيرة قبل تقرير الفوز أو الخسارة. تظهر النقاط وعدد الحركات في نافذة النتيجة، ويُنتظر حفظها قبل إعادة اللعب.
- لعبة «بالونات الحروف» تستخدم صور البالونات الأربع وخلفية التحميل واللعب وصوت الفرقعة من المرجع. تظهر الكلمات داخل جسم البالون مع حركة صعود وتأرجح وفرقعة، وشريط النقاط والمستوى والمحاولات. تُحتسب كل بالونة مرة واحدة، وتُحفظ النتيجة عند انتهاء الجولة قبل إعادة اللعب. تتوقف الحركة والصوت عند مغادرة الشاشة أو انتقال التطبيق للخلفية؛ يحتاج الشكل النهائي والصوت تجربة على الجهاز.
- شاشات تحميل الألعاب الأربع تستخدم `GameLoadingScreen` وفق `WordCatchWelcom.tsx` و`loading-screens.css`: صورة اللعبة كاملة داخل بطاقة وسط الشاشة، ونسخة مموّهة منها كخلفية، ونص بنقاط متحركة وشريط تحميل بنفسجي ووردي. العرض الأفقي القصير يرتب الصورة والنص جنباً إلى جنب؛ شاشة التحميل تظهر أثناء الطلب الفعلي دون تأخير مصطنع أو تركيب محرك اللعبة قبل اكتمال التحميل.
- معاينة ألعاب المعلم في شاشة منفصلة، دون تركيب محرك اللعب أو تشغيل مؤقتاته أو تسجيل نتائجه.
- عرض صفوف المعلم وإنشاء صف وحذفه بعد التأكيد، وجدول طلاب الصف مع نسخ كود الانضمام. تقرير الطالب يستخدم خلفيات وأيقونات الويب الأصلية ويعرض الإحصائيات وأداء الأنشطة والنشاطات الأخيرة والحروف المدروسة، مع الرجوع إلى الصف نفسه.
- صفحات الموبايل تستخدم تمريراً عمودياً فقط. الصفوف والطلاب يظهرون كبطاقات بعرض الشاشة على الهاتف، وكجداول مرنة على الشاشات الأوسع؛ لا توجد جداول أو صفحات تحتاج تمريراً أفقياً.

## ما يحتاج مراجعة واستكمال

هذه نسخة Native أولية قابلة للبناء، وليست اعتماداً نهائياً لتكافؤ تطبيق الويب:

- التصميم يعتمد على صور وخلفيات وبطاقات الحروف والأنشطة والألعاب الأصلية، وخطوط Tajawal وCairo وAmiri Quran. شاشات اختيار الحساب والدخول وصف الطالب ورئيسية المعلم والحروف والأنشطة والموارد والصفوف تستعمل هذه الأصول وترتيبها الأساسي مع تكييف العرض للهاتف والتابلت. مطابقة الصفحات بصرياً على المحاكي تحتاج مراجعة؛ الفحوص البرمجية لا تثبت التطابق البصري.
- توقيت وحركة الألعاب وحجم مناطق السحب يحتاجان تجربة على هاتف وتابلت فعليين.
- قياس التلوين يستخدم نقاطاً مأخوذة كل بكسلين من قناع Arial، بدلاً من فحص كل بكسل على Canvas. العتبة 98٪ محفوظة، لكن شكل الخط وآلية القياس ليستا مطابقين تماماً للويب.
- مكتبة موارد المعلم تعرض المكتبتين والبطاقات من بيانات الويب الأصلية. بيانات المصدر لا تحتوي روابط ملفات PDF، لذلك تظهر رسالة عدم توفر الملف عند طلب تنزيله. تعديل أسماء الصفوف وإدارة عضويتهم وبعض الشاشات الثانوية لم تُنقل بعد. تقرير الطالب يعتمد على إحصائيات الباك إند؛ دقة تجميع الدرجات والمدة والحروف تبقى مرتبطة بالبيانات التي يعيدها السيرفر.
- أي نشاط بلا محتوى في الباك إند يعرض حالة فارغة؛ لا يتم إنشاء بيانات بديلة أو تسجيله كمكتمل تلقائياً.
- يلزم اختبار تسجيل الدخول بحسابات حقيقية، الفيديو والصوت واللمس والإتاحة وسلوك العودة وخلفية التطبيق على Android وiOS. الفحوص الآلية لا تثبت هذه النقاط.
- لم يتم بناء APK/IPA، أو نشر التطبيق أو رفع تحديثات أو تغيير إعدادات حساب Expo.

## تنظيم الملفات

```text
src/app/          مسارات Expo Router وشاشات التطبيق
src/components/   مكونات الواجهة والأنشطة والألعاب Native
src/core/         API والجلسة وقواعد التلوين والألعاب
src/data/         المحتوى الأصلي وخرائط الأقنعة
assets/learning/  الصور والأصوات المنسوخة من الويب
assets/design/    صور التصميم الأصلية مع ملف sources.json لتتبع مصدر كل صورة
assets/letters/   قوالب الحروف الشفافة
tests/           اختبارات عقود API وقواعد الأنشطة
```

لتجديد أقنعة الحروف على ويندوز، من مجلد المشروع الرئيسي:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\mobile\scripts\build-letter-masks.ps1
```

## التحقق

من `mobile`:

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npx.cmd expo install --check
npx.cmd --yes expo-doctor
npx.cmd expo export --platform android --output-dir dist-android
```

التصدير يجمع كود JavaScript وأصول Android؛ لا ينتج APK ولا يغني عن الاختبار على الجهاز. الاختبارات تستخدم استجابات وهمية ولا تتصل بحسابات المستخدمين أو تكتب على السيرفر.

بعد تثبيت Android Studio يمكن تشغيل محاكي ثم `npm.cmd run android`. لإنشاء Development Build سحابياً، يوجد `eas.json` جاهز كإعداد أولي؛ لا تنفذ بناءً أو نشراً إلا بعد ربط حسابك ومراجعة معرّف التطبيق والأيقونات والتوقيع. معرّف التطبيق الحالي `com.lugati.mirati` مبدئي.
